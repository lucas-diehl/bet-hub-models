## 1. Operational lesson — NEVER run `pnpm ingest --reconcile` on this feed

**What happened:** I recommended `pnpm ingest --reconcile` to purge withdrawn CFB ATS bets. It
also removed golf and other non-ATS bets. Not a bug — it did exactly what it's designed to.

**Mechanism** (`C:\dev\bet-dashboard\packages\db\src\upsert.ts`, lines ~133–150): `--reconcile`
deletes every **ungraded** bet in the DB, scoped per `(source, sport, slate_date)`, that is **not
in the currently-emitted picks file**. But `07_write_feed.R` **rewrites each picks file every run
with only the picks that currently qualify** — so anything that dropped out of a re-emit (old ATS,
UNDERs whose line moved, golf players cut) is "not in the file" → reconcile deletes it. The two
designs are fundamentally incompatible. Plain upsert's freeze logic is what correctly preserves
posted paper bets forever.

**Recovery (non-destructive):** run **plain** `pnpm ingest` (no flag) in `C:\dev\bet-dashboard`.
Every bet still present in a feed file is re-inserted (all golf/NFL tournament files were intact;
only DB rows were deleted, not the JSON). Permanent losses = only picks no longer in any feed file
(the intended CFB ATS removals + a couple of dropped CFB UNDERs) — irrelevant for a paper track.

**Rule going forward:** `--reconcile` is banned for this feed. The scheduled task already uses
plain `pnpm ingest`, so this won't recur. Do NOT "fix" ATS-in-DB by reconcile — the `EMIT_ATS`
gate already stops NEW ATS; old frozen ATS rows are harmless paper history.

## 2. Off/def ELO + momentum deltas — TESTED, ENCOMPASSED, REJECTED

User asked: build an offense ELO and a defense ELO per team, plus rolling 1/2/4/6-week deltas as
features; see if they help.

**Built** (`data_cache/elo_features.rds`, builder in scratchpad `elo_build.R`): points-domain
split ELO from `game_info.rds`, chronological, HFA=2.0, K=0.06, 30% season regression-to-mean.
Emits pregame `elo_margin`, `elo_total`, `elo_off/def_h/a`, and momentum deltas `offmomN/defmomN/
margmomN` for N∈{1,2,4,6} (a team's pre-game rating now minus its pre-game rating N games ago).

**It is a REAL rating** (not a broken-feature false null): standalone `actual_margin ~ elo_margin`
cor=0.584, R²=0.34; `total_points ~ elo_total` cor=0.31. Just **worse than the market**: RMSE
16.97 (margin) / 16.10 (total) vs market 15.30 / 15.74 — same story as the PPD projection.

**Result — fully encompassed:**

**Takeaway:** the market prices team form/trend, not just level. This is the roadmap prediction

## 3. QB starter-out mispricing — FIRST REAL SIGNAL (needs validation)

The one category the encompassing tests said *could* survive: **new information, not projection.**

**Method** (scratchpad `qb_test.R`, table saved `data_cache/qb_game_table.rds`): from cached pbp
(`pbp_data.rds`, 1.5M plays, 2019–25) identify each team-game's QB via `passer_player_name`.
Define each team's **season-modal QB** (most dropbacks). Flag **starter-out** = that QB threw
**0 passes** in the game (a starter-absent proxy — no injury feed needed). Join to
`ppp_backtest_results.csv`; keep clean **one-sided** games (exactly one team's starter out),
push-excluded, 2021–2024 (2025 excluded — in-progress, modal QB unstable, showed 50.9% artifact).

**Result (n=603):**
- Team **starting a backup covers only 44.8% ATS** — 95% CI [40.8%, 48.8%], p=0.012.
- ⇒ **Fading the backup team = 55.2% ATS**, comfortably past the 52.4% −110 breakeven.
- Totals: backup-start games go **UNDER 53.7%** vs **49.3%** when both starters play.

**Why this is different from every prior rejection:** it's QB *availability* information, which the
market prices with a blunt adjustment — not another efficiency projection. Exactly the roadmap §5/
§7.2 hypothesis.

**Two caveats before it's actionable (do NOT deploy yet):**
1. **Look-ahead:** the flag uses the whole-season modal QB. Must be redone **as-of** — define the
   starter from PRIOR weeks only (rolling modal QB using `week < w`), then re-flag. If the 44.8%
   survives as-of, the signal is clean.
2. **Not yet bettable:** requires knowing **pregame** that a starter is out. We ingest no depth-
   chart / injury / availability feed. `starter_db==0` also includes rare in-game injuries (starter
   hurt drive 1) that weren't known pregame — the as-of redo + a conference availability-report
   feed (roadmap Phase 0) would tighten this.

**Immediate next step (the pending task):**
- Redo the starter-out flag **as-of** (prior-weeks modal QB) and confirm the ATS/UNDER effects hold.
- **Size the effect by program tier** (P5 vs G5, or by team pregame ELO / market-total level).
  Thesis: mispricing concentrates at **thin/G5 programs** where the backup dropoff is steep and the
  market's adjustment is bluntest. If the fade is strong at G5 and flat at P5, that's the
  mechanism confirmed and tells us whether an availability feed is worth building.
- Only then: assess building the pregame availability pipeline (Phase 0) to make it bettable.
