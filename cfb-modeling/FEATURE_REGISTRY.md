# Feature / Hypothesis Registry (append-only)

**Purpose:** every feature or betting-rule hypothesis tested against 2021–2025, logged
**before** its result is known, so the multiplicity budget stays honest. The project is at
~25 tests; BH adjustment already pushed the early-ATS edge from raw p=0.041 to ~0.08. Record
**rejections as diligently as survivors** — a registry of only survivors is worthless.

**Bar for deployment:** (1) beat-the-market / encompassing — `lm(target ~ line + feature)` coef
≠ 0, not raw correlation; (2) out-of-sample Brier improvement on the *bet outcome* (cover/under),
not just RMSE; (3) season-consistency + a mechanism. Every new feature must be **as-of (`week<w`)**
and asserted in `verify_pipeline.R`.

**Columns:** date · id · market · hypothesis · test · result · verdict

## Next candidates — RE-PRIORITIZED after the encompassing findings

**Key reframe:** the market encompasses our projection on BOTH markets (proj_margin p=0.76,
proj_total p=0.65) AND our components (A_prime, all p>0.35). So **projection-quality features
cannot create betting edge** — they can only improve RMSE/calibration, which the market already
beats. Only two categories can create edge, and only one is unexplored:

**A. New information the market lacks / prices bluntly (the ONLY edge avenue with a mechanism):**
- `qb_starter_out` (§5/§9.3) — **FIRST SIGNAL FOUND (2026-09).** Flag = season-modal QB threw 0
  passes that game (starter-out proxy from cached pbp, no injury feed). On clean one-sided games
  (2021–24, n=603, push-excl): the **backup-starting team covers only 44.8%** (CI [40.8, 48.8],
  p=0.012) → **fading them = 55.2% ATS**, past breakeven. Totals go UNDER 53.7% vs 49.3% both-in.
  **This is new information, not a projection upgrade — the category the encompassing tests said
  COULD survive.** **AS-OF CONFIRMED (2026-09):** re-run with a prior-weeks-only modal-QB definition
  (via `qb_elo` build) gives backup cover **45.2%** (n=564) ≈ the 44.8% whole-season number — so the
  signal is **not** a look-ahead artifact. A per-QB ELO adds **no gradient** (magnitude of downgrade
  not mispriced, see `qb_elo_gradient`) — the edge is the **binary event** (backup starting), not QB
  quality. **Remaining caveat: only bettable with a pregame depth-chart/availability feed** (roadmap
  Phase 0). Next: size the binary effect by program tier (thesis: concentrated at thin/G5 programs)
  and, if it holds, scope the availability-feed build.

**B. Display / calibration only (do NOT expect edge — fix the dashboard's over-confident probs):**
- `het_sigma` (§11.3) — σ as f(proj_total, |proj_margin|, tier). Fixes `model_prob` calibration
  (slope 0.13). Deploy for honesty of the displayed number, not for edge.

**C. De-prioritized (RMSE-only, no edge path given encompassing):** `per_metric_K` (§10.1),
`fitted_prior` (§9.1), `A_prime` (rejected), `venue_hfa`, `fixed_drives_margin`,
`neutral_script_pace`, mixed model (§11.1), ridge combination (§11.2). Each improves the
projection, which the market already encompasses — so worth it only if a *specific* one is shown
to encompass-beat the market (none has). `turnover_luck` (§9.4) is the least unlikely to shift
encompassing because it changes *what* the rating measures; test it that way if pursuing this.
